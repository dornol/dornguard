## DornGuard v0.0.3

- Reduce Java wildcard import false positives. Source-only scans report
  explicit and duplicate imports. Use `check --resolve-imports` to detect
  unused wildcard imports with the Maven or Gradle compile classpath.
  Compiler-excluded files retain source-only behavior even when old class
  files remain in the build directory.
- Run ordinary Java rules on Maven and Gradle test sources with architecture
  profiles enabled. Spring field injection remains allowed in Java tests.
  Available source checks continue after a compile failure when the project
  model can be loaded.
- Use the Java source level reported by the build, including separate main
  and test settings. Set `java_source: 25` for a source-only Java 25 check.
  `dornguard doctor` shows the Java runtime selected for ArchUnit.
- Extend Spring transaction and async self-invocation checks to direct
  calls with arguments when the same-class target can be determined. Enable
  `flyway` to review changes to existing versioned SQL migrations under
  `db/migration`, or `jpa-web` to review JPA entities declared in Spring MVC
  responses. For Flyway review in pull requests, use
  `dornguard check --changed --base origin/main`.
- Enable `format` to check indentation, line endings, final newlines,
  trailing whitespace, blank lines and control-keyword spacing in Java,
  Kotlin and JavaScript.
- Use `baseline create --resolve-imports` to build a baseline with the same
  classpath as the check. Earlier PMD fingerprints are still matched.
  Java resource warnings account for the configured target version, and
  `allow_logged_exceptions` optionally recognizes an immediately preceding
  log call that records the same caught exception.

### Upgrading from v0.0.2

The bundled ruleset is now `1.2.0`. Update a built-in
`ruleset.version: "1.1.0"` pin to `"1.2.0"`. Keep the top-level
configuration `version: 1`.

JSON check reports now use version `3`. Columns are one-based UTF-16 code
units in text, JSON and SARIF. When present, `end_line` and `end_column`
identify the exclusive end of a finding. The optional `subject` describes
the reported target. `files_requested` counts requested files, and
`files_scanned` counts files that completed all requested checks. Engine
failures can include the affected path, error type and rule IDs. Exit
codes retain their existing meanings.

See the [profile reference](https://github.com/dornol/dornguard/blob/v0.0.3/docs/profiles.md)
and [full comparison](https://github.com/dornol/dornguard/compare/v0.0.2...v0.0.3).
