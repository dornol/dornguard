## DornGuard v0.0.8

Release archives are available for Linux x86-64 (AMD64) and macOS ARM64.

- Fewer, clearer results. Architecture findings count one cause each. A package
  cycle reports one diagnostic per package edge, a forbidden dependency one per
  class, and `java.jspecify-null-marked` one per package that has no
  `@NullMarked` scope. The message and the new `occurrences` and `examples`
  fields give the count and up to three examples. See
  [how findings are counted](../architecture.md#how-findings-are-counted).
- `partial_parsing_files` lists valid files that a parser reads only partly, each
  with a reason, so they are reported as incomplete analysis instead of an
  engine error. `partial_parsing: warning` does the same for every file. It
  applies to Semgrep and the JSpecify declaration parser.
- `java.unnecessary-import` no longer reports an import whose type the file also
  writes in full. `java.fully-qualified-type` reports it once and asks for the
  simple name, so removing the import is no longer the suggested fix.
- Fewer false positives. `java.empty-catch` allows a block that has a comment.
  `java.preserve-stack-trace` accepts rethrowing the caught exception after an
  `instanceof` check. `java.resource-not-closed` ignores an `instanceof` binding
  that the code never closes and a local that borrows a field, a variable or the
  result of a plain `getX()` call. `getConnection`, `getResourceAsStream`,
  `getInputStream` and `getOutputStream` still count as opening a resource.
- Suppressions for rules that are not active in a run, for example with
  `--only-profile`, are no longer reported as obsolete.
- `format.indentation` is off by default. Enable it with
  `rules: { format.indentation: { enabled: true } }`, or use a formatter such as
  Spotless, google-java-format, ktlint or Prettier.
- The `format.*` rules skip test sources like every other rule. Set
  `skip_java_tests: false` on a rule under `rules` to check them. The key is now
  accepted for every rule.
- The CLI finds the bundled `archunit-runner.jar` and `maven-model.jar` when the
  executable is installed through a symlink, such as `~/.local/bin/dornguard`.
  `dornguard doctor` reports both without a configuration file.

### Upgrading from v0.0.7

Use built-in ruleset `1.6.0` and top-level configuration `version: 1`.
Install the CLI and bundled JVM artifacts together. The ArchUnit runner
protocol is still 5.

A project that enabled the `format` profile loses its indentation check until
it sets `format.indentation: { enabled: true }`, and no longer sees formatting
findings in test sources unless a rule sets `skip_java_tests: false`.

Counts drop because findings are grouped. A baseline or an `ignore` entry with
a fingerprint that was recorded for the individual dependencies still matches
the group that replaces them, so existing suppressions keep working. After
upgrading, run `dornguard baseline create --force` to record the grouped
findings and drop entries that no longer occur.

A grouped fingerprint covers every dependency in its package edge, class or
package, including ones added later. Review a new dependency in an already
baselined group when you add it.

JSON check reports remain version 3. Grouped diagnostics add optional
`occurrences` and `examples`, and SARIF carries them in the result's
`properties`. Other diagnostics are unchanged.
