## DornGuard v0.0.7

Release archives are available for Linux x86-64 (AMD64) and macOS ARM64.

- Rules now skip test sources, any file below a `src/test` directory, by
  default. `java.assert-throws-nested-call` and the `format.*` rules still
  check tests. A rule can opt back in with `skip_java_tests: false`. The report
  notes how many test files were skipped.
- Fewer security false positives. `security.sql-injection` ignores signing and
  hashing calls such as `Signature.update`, constant concatenation, and strings
  without SQL keywords. `security.csrf-disabled` skips methods that set
  `SessionCreationPolicy.STATELESS`. `security.disabled-tls-verification` skips
  code behind an option such as `verifySsl` or `insecure`.
- New `kotlin.sql-injection` in the `kotlin` profile reports Kotlin SQL built
  from templates, concatenation, or formatting.
- `java.stdout-usage` and `kotlin.stdout-usage` no longer report output inside
  a `main` entry point. Helpers that `main` calls are still reported.
- `spring.field-injection` also reports `@Inject` and `@Resource` fields and
  annotations with arguments such as `@Autowired(required = false)`. Its fix
  text explains constructor injection, Lombok's `@RequiredArgsConstructor`,
  and `@Qualifier` handling.
- Rules declare a `confidence` of `high` or `medium`. Each JSON diagnostic
  includes it, `dornguard rules explain` shows it, and the text and agent
  reports add a `Review:` line to `medium` findings. A `medium` rule infers
  intent from code shape, so confirm the finding or suppress it with a reason.
  Confidence does not change severity or exit codes. See
  [rule confidence](../profiles.md#rule-confidence).
- Baselines gain two options. `--strict-changed` reports baselined findings in
  the files that `--changed` selected, so legacy findings shrink where people
  edit. `--ratchet` fails a complete full scan when the baseline records
  findings that no longer occur.
- A complete full scan lists `ignore` entries and `dornguard-ignore` comments
  that matched no finding, so you can remove obsolete suppressions.
- A Thymeleaf template that Semgrep parses only in part now reports the line
  and column where parsing stopped, with a hint for a literal `>` or `&` or a
  duplicated closing tag.
- A `--changed` check on a JPA project falls back to a full scan only when a
  changed Java file mentions persistence.

### Upgrading from v0.0.6

Use built-in ruleset `1.5.0` and top-level configuration `version: 1`.
Install the CLI and bundled JVM artifacts together. The ArchUnit runner
protocol is still 5.

Test sources are no longer checked by most rules, so a project that relied on
those findings sees fewer of them. Set `skip_java_tests: false` on a rule to
keep checking tests. `spring.field-injection` can report fields that earlier
versions missed. The other changes remove findings that were false positives.

JSON check reports remain version 3. Each diagnostic adds a `confidence` field.
