## DornGuard v0.0.4

Release archives are available for Linux x86-64 (AMD64) and macOS ARM64.

- Agent reports show a representative finding for each rule before repeating
  findings of the same severity. Use `--report-rule` and `--report-path` to
  narrow the displayed findings while keeping the check scope, counts and
  exit code. `dornguard init --help` includes a copyable configuration.
- Opt in to `java-review` to catch discarded Java return values and nested
  calls in JUnit exception assertions. Both rules start as warnings.
- JSON findings can provide an edit for trailing whitespace or a missing
  final newline. Each edit includes a UTF-8 byte range, replacement text
  and the original file's SHA-256. Verify the hash before applying it and
  rerun the check afterward.
- Source rules keep checking eligible files outside build module source
  roots when architecture profiles are enabled. Git-tracked sources remain
  eligible when they match `.gitignore`. Architecture checks report skipped
  compiler inputs or stale Maven classes as incomplete. A partial format
  parse also reports incomplete analysis.
- Configure file and directory ignores, per-rule exceptions, source glob
  exclusions and file-specific formatting overrides. Use `--only-profile`
  to select a profile such as `format` for a single run. The CI guide shows
  how to gate new blocking findings against the base branch's baseline.
- Java and Spring checks recognize more resource ownership, exception and
  transaction patterns. HTML and Thymeleaf findings support reasoned
  comments, and Thymeleaf can recognize explicitly configured sanitizers.
  Architecture findings are grouped by class dependency, and `doctor`
  validates the runner protocol for active architecture profiles.

### Upgrading from v0.0.3

Install the matching CLI and JVM artifacts together. ArchUnit runner
protocol changes from 3 to 4. The release archive includes the matching
runner and Maven model extension.

Update any built-in `ruleset.version: "1.2.0"` pin to `"1.3.0"` and keep the
top-level configuration at `version: 1`. Existing fingerprint ignores and
baseline files remain readable.

JSON check reports stay at version 3. Consumers can read the new
`rule_counts`, optional `edit` and `report_filter` fields, and the separate
`project_scope` and `organization_scope` when organization policy is enabled.
An organization's full scan makes the combined `scope` full.
