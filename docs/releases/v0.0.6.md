## DornGuard v0.0.6

Release archives are available for Linux x86-64 (AMD64) and macOS ARM64.

- New security rules in the `security` profile: `security.sql-injection`,
  `security.weak-crypto`, `security.disabled-tls-verification`, and
  `security.csrf-disabled`. The profile is included in `rest-api`.
- New Spring rules in `spring-boot`: `spring.cache-self-invocation` and
  `spring.retry-self-invocation` report same-class calls that bypass Spring's
  cache and retry proxies.
- `java.print-stack-trace` and `kotlin.print-stack-trace` join the
  `java-source` and `kotlin` profiles. `kotlin.transactional-suspend` reports
  Spring `@Transactional` on a `suspend` function, which needs a reactive
  transaction manager.
- Add the `package-cycles` profile to reject dependency cycles between
  packages in a module. The rule reports each class dependency that crosses
  between packages of the same cycle.
- Architecture rule options accept `cycles: true` in place of `forbidden`.
  A rule uses one or the other.

### Upgrading from v0.0.5

Use built-in ruleset `1.4.0` and top-level configuration `version: 1`.
Install the CLI and bundled JVM artifacts together. The ArchUnit runner uses
protocol 5, so a v0.0.5 runner does not work with this CLI.

The new rules are active in their existing profiles, so projects that already
use `security`, `rest-api`, `spring-boot`, `java-source`, or `kotlin` can see
new findings. Lower a rule's severity or disable it in `.dornguard.yml` with
`enabled: false` when it does not fit. `security.csrf-disabled` and
`kotlin.transactional-suspend` are warnings because some projects use them
deliberately.

JSON check reports remain version 3.
